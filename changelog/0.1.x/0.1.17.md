# 0.1.17 — 2026-08-25

## Added

- **`.github/CONTRIBUTING.md`** and **`.github/CODE_OF_CONDUCT.md`** added.

## Changed

- **`@cyanheads/mcp-ts-core`** `^0.11.0` → `^0.12.3` adopts the breaking MCP SDK v2 migration: every HTTP endpoint now also serves protocol revision `2026-07-28` alongside the 2025 era, tool inputs are strict (an argument key a tool's schema doesn't declare is now rejected by name instead of silently stripped), each tool's advertised `outputSchema` now declares the `error` envelope, and advertised JSON Schema moved from draft-07 to 2020-12. No tool, parameter, or output field of this server changed — the strict-input tightening only rejects keys that were already outside the documented schema.
- **`src/services/wikipedia/wikipedia-service.ts`** log/error sites moved from spreading the handler context (`{ ...ctx, … }`) onto the log call to `withExtra(ctx, { … })`; the deprecated `RequestContextLike` replaced with `RequestContext` across every service method signature, and the ad-hoc `(ctx as { signal?: AbortSignal })` cast replaced by a declared `ServiceContext` type.
- **`MCP_SESSION_MODE`** settled on `stateless` in `.env.example`, `Dockerfile`, and a new README env-table row. The Docker image's behavior is unchanged — it already ran `stateless` — this closes a doc split where `.env.example` claimed `stateful` and omitted the schema's actual `auto` default.
- **Toolchain** — Bun `1.3.14` → `1.4.0` in both `Dockerfile` stages and `package.json` `packageManager` (`engines.bun` stays `>=1.3.0`); `--omit=peer` added to the production `bun install` and the OTEL `bun add` in `Dockerfile`; `tsconfig.json`/`tsconfig.build.json` split typecheck from emit, so `tests/` is now typechecked.
- **`.github/SECURITY.md`** reported security contact changed to `security@caseyjhand.com`.
