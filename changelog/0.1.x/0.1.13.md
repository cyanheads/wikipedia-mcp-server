# 0.1.13 — 2026-07-16

## Added

- **`wikipedia_search` pagination** — new `offset` input (default 0, maps to the Action API `sroffset`) pages beyond the first capped result page. Enrichment gains `offset` (echo), `shown` (results on this page), and `nextOffset` — present only while more results remain, pass it back as `offset` to continue ([#22](https://github.com/cyanheads/wikipedia-mcp-server/issues/22)).

## Changed

- **`wikipedia_get_article` overflow** — a full-article read (no `section_index`) above the new `WIKIPEDIA_ARTICLE_OVERFLOW_BYTES` budget (default 80000) now returns a compact section outline (`truncated: true`, pointing to `wikipedia_get_sections`) instead of the full text, via the `@cyanheads/mcp-ts-core` `outlineOnOverflow` primitive. Adds optional `original_length` and `sections_suggested` output fields alongside the always-present `truncated`. Section-targeted reads are unchanged and the wire contract stays additive, but large full-article reads change shape for existing callers ([#23](https://github.com/cyanheads/wikipedia-mcp-server/issues/23)).

## Fixed

- **`wikipedia_search` and `wikipedia_search_nearby` `pageid`** field descriptions no longer claim page IDs can be passed to follow-up tools, which accept titles — reworded as a stable reference id for cross-referencing and de-duplication, steering agents to pass the title instead ([#21](https://github.com/cyanheads/wikipedia-mcp-server/issues/21)).
