# 0.1.14 — 2026-07-29

## Changed

- **Edition validation** replaces the hand-maintained 227-code `KNOWN_WIKIPEDIA_EDITIONS` allowlist with a registry built from the MediaWiki `action=sitematrix` endpoint, cached in the injected `StorageService` under a 24h TTL plus an in-process memo and a shared in-flight promise for concurrent callers. The old list rejected ~49 real editions (`ht`, `yi`, `vo`, `haw`, and others) and contained `hat`, which is not a Wikipedia subdomain. A sitematrix outage degrades to an offline fallback set (`hat` removed) rather than failing the call ([#26](https://github.com/cyanheads/wikipedia-mcp-server/issues/26)).
- **`wikipedia_get_languages`** resolves a missing-`url` langlinks entry from the same edition registry instead of composing `https://<language_code>.wikipedia.org`, which produced a nonexistent host for editions whose language code differs from their subdomain (`gsw` → `als.wikipedia.org`). `edition_code` and `url` are now `.optional()` and omitted together when no host is known, rather than fabricated ([#24](https://github.com/cyanheads/wikipedia-mcp-server/issues/24)).
- **`wikipedia_get_languages`** now passes `redirects: 'true'` to the Action API, matching the other read tools, and returns the resolved title as `source_title` instead of echoing the input — a redirect alias previously reported `no_other_languages` instead of the target's interwiki links ([#27](https://github.com/cyanheads/wikipedia-mcp-server/issues/27)).
- **`wikipedia_search_nearby`** `limit` clamp raised from 50 to the upstream `gslimit` ceiling of 500 (`GEOSEARCH_MAX_LIMIT`), with `.max(500)` added to the Zod validator. `truncated` is established by requesting one result past the limit and reporting the overflow, so a match count landing exactly on `limit` no longer false-positives. The generic truncation notice is replaced with guidance the tool can act on — raise `limit`, or reduce `radius_meters` and sweep sub-areas — since geosearch has no pagination and the tool has no filter parameters ([#29](https://github.com/cyanheads/wikipedia-mcp-server/issues/29)).
- **`wikipedia_search_nearby`** `radius_meters` validator gained `.min(10)`, matching the `gsradius` floor `action=paraminfo` reports. A radius of 1–9 previously reached the API and returned a raw `outofrange` error; it now fails Zod validation with the bound named in the message. Both bounds are exported as `GEOSEARCH_MIN_RADIUS_METERS` / `GEOSEARCH_MAX_RADIUS_METERS` ([#30](https://github.com/cyanheads/wikipedia-mcp-server/issues/30)).

## Fixed

- **Structural language check** (`isMalformedLanguage`, replacing the inline `/^[a-z]{2,3}(-[a-z0-9]+)*$/i` literal duplicated across all six tool handlers and the service) widens the first BCP 47 subtag from 2–3 to 2–8 characters, so `simple` (`simple.wikipedia.org`) resolves instead of failing the shape check ahead of the edition registry ([#31](https://github.com/cyanheads/wikipedia-mcp-server/issues/31)).

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.10.14` → `^0.11.0`, bringing TypeScript 7 (`typescript` `^6.0.3` → `^7.0.2`).
