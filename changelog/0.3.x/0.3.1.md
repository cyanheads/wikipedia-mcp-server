# 0.3.1 — 2026-11-11

## Added

- **`wikipedia_get_languages` `editions` classification**: every requested code lands in one place, its `languages` entry, `source_editions` (the edition you queried), `unknown_editions` (not a Wikipedia edition), or `missing` (no article there) ([#76](https://github.com/cyanheads/wikipedia-mcp-server/issues/76), [#80](https://github.com/cyanheads/wikipedia-mcp-server/issues/80)). The legacy codes `nb`, `be-x-old`, and `egl` are accepted on every tool.
- **`wikipedia_get_sections` returns `categories` and `page_type`**, and **`wikipedia_get_article` flags disambiguation pages** on every read path, section and table reads through a best-effort lookup that adds a notice when it fails ([#77](https://github.com/cyanheads/wikipedia-mcp-server/issues/77), [#83](https://github.com/cyanheads/wikipedia-mcp-server/issues/83)).
- **`wikipedia_get_summary` reports `redirected_from` and `redirect_section`**, and `wikipedia_get_references` reports `redirect_section`; the summary `url` is composed like the other reads ([#86](https://github.com/cyanheads/wikipedia-mcp-server/issues/86)). The summary `page_type` description lists `mainpage`.
- **`wikipedia_search_nearby` discloses a clamped radius** with `requestedRadiusMeters` and a notice; the ceiling is 10,000 m ([#82](https://github.com/cyanheads/wikipedia-mcp-server/issues/82)).

## Changed

- **`wikipedia_search_articles` `limit`** goes up to 500 per page, clamped above that with a notice; descriptions and QIDs load in chunks of 50 ids, at most 4 in flight process-wide, within one shared 5 s budget ([#84](https://github.com/cyanheads/wikipedia-mcp-server/issues/84)).
- **A 2xx response whose body is not a JSON object** (an HTML page, XML, truncated text, a bare `null`) is retried, then fails as `ServiceUnavailable` with one fixed message ("Wikipedia <API> returned a response that is not a JSON object — likely rate-limited or under maintenance."). The error code moves from -32007 to -32000 for non-JSON bodies; a `null` summary body no longer surfaces as an internal error.
- **The optional table-of-contents lookup** degrades on any upstream failure instead of failing the read.
- **Notices that quote caller or upstream text** are escaped in `content[]`.
- **`wikipedia_get_languages` `content[]`** renders each requested code in its own code span, so a code containing ", " reads as one code.
- **Server instructions and the `wikipedia-guide` skill** name `page_type` on `wikipedia_get_sections` and `wikipedia_get_article`.

## Fixed

- **Lists keep their markers and nesting on every read path**: `- ` and `N.` lines with `start`, `reversed`, and `value` honored, two spaces per level, indentation capped at 16 levels ([#81](https://github.com/cyanheads/wikipedia-mcp-server/issues/81)).
- **A source line break inside a paragraph** reads as a space, except between two wide East Asian characters, where it is dropped as a browser drops it.
- **`Special:` and `Media:` titles in any edition's spelling** are `invalid_title` on every read tool, as are interwiki titles (`wikt:cat`) and invalid entries such as `Talk:`; the summary checks a title containing `:` with one request before REST ([#87](https://github.com/cyanheads/wikipedia-mcp-server/issues/87)).
- **The edition registry** is built independently of any one caller's cancellation, and while it is unavailable no code is claimed unknown. Language links without a URL resolve their host through the edition index.
- **`wikipedia_get_languages` with `editions`** succeeds with `languages: []` on an article that has no other editions ([#76](https://github.com/cyanheads/wikipedia-mcp-server/issues/76), [#80](https://github.com/cyanheads/wikipedia-mcp-server/issues/80)).
