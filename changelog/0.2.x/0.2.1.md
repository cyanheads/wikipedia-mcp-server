# 0.2.1 — 2026-09-17

## Added

- **`section_index: 0`** on `wikipedia_get_article` reads the lead section — the text above the first heading — and `wikipedia_get_sections` lists it as its first entry (`index: 0`, title `Introduction`) (#40).
- **`wikipedia_search_articles`** discloses when a result page is cut at Wikipedia's 10,000-result search window, via enrichment `truncated`/`cap` naming the matches no `offset` can reach (#41).
- The four title-taking tools (`wikipedia_get_article`, `wikipedia_get_sections`, `wikipedia_get_summary`, `wikipedia_get_languages`) refuse a title MediaWiki cannot name a page with, with a typed `invalid_title` reason, before any fetch (#42).

## Changed

- **`wikipedia_get_sections`**'s `total_sections` now counts the lead entry (#40).
- **`wikipedia_search_articles`**'s `limit` above 50 and `offset` at or past the 10,000-result search window now reject instead of clamping or returning an empty page (#41).
- Titles carrying `< > [ ] { }` or `|`, percent escapes, three or more tildes, or relative paths now reject with `invalid_title` instead of answering (#42).
- Server `instructions` reshaped into a single cohesive paragraph.

## Fixed

- **`wikipedia_search_articles`** now fails on an empty `query`, rather than returning a successful empty result (#41).
- The Action API's `error` envelope, which arrives on HTTP 200, is now read before the payload on every call site (`search`, `getArticleFull`, `getSections`, `getArticleSection`, `getLanguages`, `searchNearby`, `fetchEditionIndex`) — an upstream refusal no longer renders as a successful empty result (#41, #42).

## Dependencies

- `@cyanheads/mcp-ts-core` `^0.13.2` → `^0.13.3`
