# 0.2.6 — 2026-10-08

## Changed

- **Tool arguments** — a numeric string for a number argument (`latitude`, `longitude`, `limit`, `offset`) and `null` for an optional argument (`section_index`, `editions`, `limit`) are repaired before validation and the call succeeds; both were rejected with `-32602` (framework 0.13.14).
- **Error results** — `structuredContent.error.data` carries `requestId`, and the `content` text ends `(reason <reason> · request <id>)` (framework 0.13.10).
- **Error data** no longer carries server stack traces (0.13.7), request context such as tenant and operation fields (0.13.8), or `rootCause` (0.13.13).
- **Argument-rejection hints** name each field's path, e.g. `Send query as a string, not a boolean.` (framework 0.13.9).
- **Tool and service error throws** drop the `...ctx.recoveryFor(...)` spreads and the service's hard-coded `invalid_title` hint; the framework fills the hint each tool's error contract declares (0.13.10). The hint text clients see is unchanged.
- **`server.json`** — both npm entries take `"runtimeHint": "npx"` and drop the `run` / `start:*` arguments a registry client would pass to the package's bin; the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` to `http` (0.13.11 template).
- **Docker** — production dependencies install in a `deps` stage on the build platform, musl-only packages are pruned, and the Bun base images move 1.4.0 → 1.4.2 (`packageManager` `bun@1.4.2`; 0.13.10, 0.13.11).
- **`.env.example`** documents `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, `MCP_REQUEST_STATE_KEY`, the per-signal OTLP endpoints, and `LOG_LLM_INTERACTIONS`; the README adds a `LOG_TOOL_FAILURE_PAYLOADS` row and condenses its per-tool capability reference.
- **Packaging** — `package.json` `files` excludes `dist/*.mcpb` from the npm tarball; `.mcpbignore` also leaves `logs/`, `.cache/`, `coverage/`, `tests/`, and `docs/idea.md` out of the bundle; `.gitignore` and `.dockerignore` ignore `.env*` except the example files.
- **Tooling** — `scripts/` (`lint:packaging` gains Dockerfile build-platform, `server.json` launch-shape, `manifest.json` version, and tarball checks), `framework-skills/`, and `CLAUDE.md` / `AGENTS.md` sync to the 0.13.14 template.
- **CodeQL workflow** runs one job per language, each uploading under `/language:<language>`.
